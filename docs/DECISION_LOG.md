# Decision Log

Format: ID — date — decision — reason — status.

## D-001 — 2026-11-17 — Pin Godot 4.7.2-stable
Latest stable Godot 4.x at project creation (checked against official
`godotengine/godot` tags). Standard (GDScript) build, not .NET. Upgrades only
between milestones with a tested migration. **Accepted.**

## D-002 — 2026-11-17 — Mobile renderer
`rendering_method` and `rendering_method.mobile` both `mobile`, per spec §9.1.
ETC2/ASTC texture import enabled for Android. A compatibility test scene for
low-end devices is deferred until there is something to render (Milestone 1+).
**Accepted.**

## D-003 — 2026-11-17 — Sensor landscape orientation
`display/window/handheld/orientation = 4` (sensor landscape): landscape only,
but the device may rotate 180° so players can hold it either way. Portrait is
never allowed. **Accepted — revisit if device testing shows problems.**

## D-004 — 2026-11-17 — Viewport 2400×1080, canvas_items + expand
Matches the spec's design reference; `expand` adapts to other aspect ratios.
Desktop window override 1200×540 for editor testing. UI respects device safe
areas through `SafeAreaMargin` (min. 48 px from edges). **Accepted.**

## D-005 — 2026-11-17 — In-house headless test runner
`tests/run_tests.gd` instead of a third-party plugin (e.g. GUT), per spec §9.1
rule on reviewing plugins first. Can be revisited if test needs outgrow it.
**Accepted.**

## D-006 — 2026-11-17 — Input map generated by script
`tools/configure_input_map.gd` writes the input map to `project.godot` so
bindings are reproducible and reviewable. Editing in the Godot editor is also
fine; re-running the tool overwrites those 12 actions. Joypad events use
device −1 (any controller). **Accepted.**

## D-007 — 2026-11-17 — Specification stays in one place
`docs/PRODUCTION_PACKAGE.md` is canonical. Topic docs (GAME_DESIGN,
TECHNICAL_ARCHITECTURE, …) point to its sections and only add
implementation-level detail as milestones land, to avoid two conflicting
sources of truth. **Accepted.**

## D-008 — 2026-11-17 — Provisional Android package name
`com.vanguardbloodline.prototype`. Package names are permanent once published
on Google Play, so the final ID must be chosen with the final title/legal
review before any store upload. arm64-v8a only for now. **Provisional.**

## D-009 — 2026-11-17 — Scene changes via SceneRouter autoload
Single autoload guards against overlapping transitions (spec §9.3). Scene paths
are listed in `scripts/app/scene_paths.gd`. **Accepted.**

## D-010 — 2026-11-18 — Typed Resources are the canonical gameplay data format
Gameplay data uses typed custom `Resource` scripts saved as `.tres` in `data/`
(e.g. `ArenaConfig`, `FighterMovementProfile`). Gives editor validation and
typed access; each type has a `validate()` method used at scene start and in
tests. No parallel JSON copies (spec §9.5). Resolves the M1/M2 open decision.
**Accepted.**

## D-011 — 2026-11-18 — Own kinematic simulation, not the physics engine
Fighters are simulated by `CombatSimulation` (plain `RefCounted`, no nodes)
moving along X only, instead of `CharacterBody3D`/physics. Reasons: exact
determinism, explicit phase ordering, testable without a scene tree, and no
physics-engine behaviour tied to frame timing. Scene nodes are views only
(`FighterView`). The spec's fighter scene tree is adapted accordingly
(§9.2 allows node changes if responsibilities stay clear). **Accepted.**

## D-012 — 2026-11-18 — Fixed 60 Hz tick with render interpolation
`CombatClock` accumulates render delta and returns whole 60 Hz ticks; max 5
catch-up ticks per frame, excess time is dropped (no spiral of death). Views
interpolate between the previous and current tick (`alpha`). Tests prove the
same per-tick positions at 30/60/90/120/144 fps and jittery frame times.
**Accepted.**

## D-013 — 2026-11-18 — Movement rules and step order
Step phases: intent → integrate (forward/back speed relative to facing) → max
separation → pushbox resolve (walls win) → wall clamp → facing. Always P1
before P2. Fighters face each other every tick; walking cannot cross the
opponent (side switches arrive with jumps/throws later). Max separation 6 m
keeps both fighters framable. Starting tuning: forward 2.6 m/s, back 2.0 m/s,
pushbox half-width 0.35 m, arena walls ±6 m. **Accepted — tune in playtests.**

## D-014 — 2026-11-18 — Camera framing
Side-on, fixed pitch −5°, no rotation. FOV 30° vertical, distance 6.5–14 m,
1.5 m edge margin, exponential smoothing with a hard visibility guarantee
(fighters can never leave the frame, even while smoothing lags). Near walls
the frame may show at most 0.5 m beyond the wall. Max distance covers 4:3
tablets at max separation. **Accepted.**

## D-015 — 2026-11-18 — Temporary debug touch buttons
The greybox overlay has labelled "DEBUG ◀ ▶" buttons that press the same
logical actions as the keyboard, so movement can be tried on a phone before
Milestone 4 touch controls. They will be removed when the real touch layout
lands. Android back gesture / "Menu" button return to the main menu until the
pause menu (M3). **Accepted — temporary.**

## D-016 — 2026-11-18 — Test runner runs on first frame
Tests execute on the runner's first idle frame so integration tests can add
real scenes to a live tree. Because GDScript can't catch runtime script errors,
CI also fails if `SCRIPT ERROR`/`ERROR` appears in the log, and integration
tests assert that the scene initialised before checking anything. **Accepted.**

## D-017 — 2026-11-18 — Per-tick hitbox overlap sampling
Hitboxes/hurtboxes are axis-aligned rectangles on the fighting plane, tested
once per tick after movement. No tunnelling is possible at current speeds
(< 0.05 m/tick, fighter-relative boxes, ≥ 1 active tick). Swept tests will be
added only for fast projectiles. Resolves the M2 open decision. **Accepted.**

## D-018 — 2026-11-18 — Frame-data convention
Startup includes the first active frame (fighting-game standard); stun N =
N ticks without control; advantage formulas in `docs/COMBAT_FRAME_DATA.md`.
Spec §4.4 numbers are read with this convention. **Accepted.**

## D-019 — 2026-11-18 — Combat rules for M2
Block = hold BLOCK button (not hold-back), standing block covers high/mid;
chip can KO; simultaneous hits trade; getting hit interrupts attacks; global
hitstop; corner pushback transfers to the attacker; only neutral fighters turn;
attack button priority Heavy > Kick > Light. **Accepted — revisit in playtests.**

## D-020 — 2026-11-18 — FighterDefinition resource
`FighterDefinition` (health, movement profile, hurtbox, move list) replaces
passing movement profiles directly. Moves are found by `input_pattern`.
Spec §4.3 fields are all present on `MoveData`; cancel tags, meter, knockdown,
launch, airborne and cooldown are stored but not simulated until their
milestones. Kairo heavy pushback set to 0.2 m so it stays punishable on block
at close range. **Accepted.**

## D-021 — 2026-11-18 — Training dummy modes (not AI)
P2 is driven by `TrainingDummyController` with STAND / BLOCK / JAB modes
(T / F6 / on-screen button). Output depends only on the tick — no reactions,
no reading P1. The real AI is Milestone 5. **Accepted.**

## D-022 — 2026-11-18 — Match flow owned by MatchDirector
A deterministic `MatchDirector` (RefCounted) wraps the simulation with phases
INTRO → FIGHT → ROUND_END → (next INTRO | MATCH_END). Inputs reach the
simulation only in FIGHT. Round timer is integer ticks (90 s = 5,400), never
negative, counts every FIGHT tick (including hitstop). Rules live in
`data/rules/standard_match.tres` (`MatchRules`). **Accepted.**

## D-023 — 2026-11-18 — Draw and termination rules
Time-out with equal health, or a double KO, is a draw round that awards both
fighters a round win (`draw_awards_both`). If both reach the win target at
once the match is a draw. A `max_rounds` cap (5) guarantees termination even
if draws award nothing. No overtime rule yet (spec allows either). **Accepted —
revisit with playtests.**

## D-024 — 2026-11-18 — Pause via SceneTree.paused
Pause freezes the whole combat scene (simulation, effects, camera); only the
pause menu runs. No catch-up happens on resume. Auto-pause on app focus loss
/ background. Android back opens/closes the pause menu (replaces the M1/M2
"back to menu" behaviour). Pause is disabled once results are showing. Leaving
the scene always unpauses the tree. **Accepted.**

## D-025 — 2026-11-18 — Debug "Reset" becomes "Restart match"
With rounds in place, a mid-match health reset would bypass match rules. R/F5
now restarts the whole match (same as the pause menu). The on-screen Reset and
Menu debug buttons are removed (pause menu covers them). A proper Training
mode (infinite time, reset positions) is part of M4/M7. **Accepted.**

## D-026 — 2026-11-18 — Input buffer in the simulation
Each fighter keeps a buffer of attack presses with tick ages (6-tick window,
`CombatTuning`). Ages freeze during hitstop so presses made during a hit
remain usable. Newest legal press wins; illegal presses are kept until they
expire. Replaces the M2 hitstop latch. **Accepted.**

## D-027 — 2026-11-18 — Cancel model: tags + window + repeat limit
`MoveData.tags` (what a move is) and `MoveData.cancel_tags` (what it may
cancel into). Cancel only on contact, within active frames + 3 grace
frames, max 2 uses of the same move per chain. Kairo: Light → Light/Kick;
Heavy and Kick → specials (none yet). **Accepted.**

## D-028 — 2026-11-18 — Combo counting and scaling
Combo counted on the defender (hit while in HITSTUN), reset on recovery or
block. Scaling 100/100/80/70/60/50, floor 40 %, integer maths, min 1. HUD
shows "N HITS" on the attacker's side from 2 hits. **Accepted — tune later.**

## D-029 — 2026-11-18 — Touch controls
Custom multi-touch layer (`TouchControls`) tracking fingers by index:
floating stick in the outer 33 % below the HUD, diamond action cluster
(Heavy top, Light inner, Kick bottom, Block outer), 100 px radius at 1080p
with 15 % hit slop, touch-down activation, finger keeps its button until
lifted. Left-handed mirror toggle in the pause menu (not persisted until the
M7 save system). Size/opacity are exported properties ready for M7 settings.
Shown on touchscreens and in debug builds. **Accepted.**

## D-030 — 2026-11-18 — Training mode
`MatchRules.training`: straight to FIGHT, ∞ timer, no rounds, no KO (health
floor 1), health refills when neutral, Reset button / R resets positions.
Implemented as `training_greybox.tscn` (inherits the versus scene, different
rules). Training panel: combo hits/damage, last hit + scaling, last move frame
data and advantage, P1 input history. **Accepted.**

## D-031 — 2026-11-18 — FSM AI with delayed, human-visible perception
`AIController` is a finite-state machine (spec §5 states) driven only by
`AIObservation` snapshots. The whole screen — including the AI's own fighter
— is perceived `reaction_delay_ticks` late. Output is a normal
`FighterInputFrame`. Frame data is treated as public matchup knowledge.
Seeded RNG for reproducibility. **Accepted.**

## D-032 — 2026-11-18 — Three difficulty profiles as data
`data/ai/{beginner,standard,expert}.tres` (`AIProfile`). Knobs: reaction
delay, decision interval, anticipation, aggression, move weights, close
Light bias, range mistakes, combo commit, block/guard/punish/mash chances,
predictable pattern (Beginner), adaptive (Expert), anti-idle. No stat knobs
exist on the type. Values and benchmark in `docs/AI_TUNING.md`. **Accepted —
tune with human playtests.**

## D-033 — 2026-11-18 — P2 controller selection
Versus: P2 = AI at the difficulty chosen on the main menu ("AI: …" button,
session-only `SessionSettings` until the M7 save system). Training: P2 =
dummy. T / the debug "P2:" button cycles AI Beginner/Standard/Expert and
dummy STAND/BLOCK/JAB. HUD shows "… — CPU <level>" or "— Dummy". AI is
re-seeded per match. **Accepted.**

## D-034 — 2026-11-18 — Kairo is a scripted, from-scratch blockout
No final model exists yet, so Kairo is built by `tools/blender/build_kairo_blockout.py`
from primitives (no base mesh, no external assets), rigged to a Godot-humanoid
skeleton with rigid skinning, animated with IK-placed key poses whose active
frames come from the move data, and exported as GLB. Clearly labelled
`BLOCKOUT`. Final art replaces it under the same conventions
(`docs/BLENDER_PIPELINE.md`). **Accepted — placeholder.**

## D-035 — 2026-11-18 — Animation follows the simulation
`FighterAnimator` seeks attack animations to the move frame (frame N = tick
N) and freezes reactions during hitstop; the AnimationPlayer is never the
combat clock (spec §9.3). Tests sample the real model on every active frame
and require the striking limb inside the hitbox. **Accepted.**

## D-036 — 2026-11-18 — Specials, meter, Surge and ultimate model
Special = Origin Palm (25 meter); toward+Special = Rift Break (free, moves,
knockdown). Ultimate button: at full meter → Origin Surge (readable 20-frame
activation, 5 s, meter drains, ×1.15 damage, free specials); during Surge →
Origin Break (needs ≥ 30, spends all, ends Surge). Meter carries between
rounds. Knockdown/get-up are invulnerable and end combos. **Accepted — tune
in playtests.**

## D-037 — 2026-11-18 — Ultimate cinematic is presentation-only
The ultimate's 60-tick hitstop is the "cinematic"; the camera pushes in
(bounded, fighters and HUD stay visible) and returns. Any touch/key skips
the camera move without changing the simulation, so it stays deterministic
and could later run online. `CameraRig.cinematics_enabled` is the hook for
the reduced-motion setting. **Accepted.**

## D-038 — 2026-11-18 — Placeholder audio is synthesized in-repo
`tools/audio/generate_placeholder_sfx.py` creates original `placeholder_*.wav`

## D-045 — 2026-11-18 — Sculpt-style hero pipeline with smooth skinning
After owner feedback that the roster looked toy-like, `hero_builder.py`
builds fighters as layered shells: overlapping anatomical forms are
voxel-remeshed into one surface, smoothed, decimated, then skin weights and
paint colours are transferred from the source forms and blurred. Colour is
per-vertex (materials only set roughness/metal/emission). Rigid skinning
(D-039) is superseded for these fighters; the rig and animations are
unchanged. Kairo, Sentinel and Warden use it; the five locked fighters still
use the older builder until M8. **Accepted — pending owner review on device.**

## D-051 — 2026-11-20 — Arena quality pass: textures, baked AO, motion
To move the arenas from flat colours towards console-stage quality while
staying phone-friendly:
- **Textures:** 14 tileable surface sets (albedo/normal/roughness, 512 px,
  VRAM-compressed with mipmaps) generated from scratch by
  `tools/art/make_arena_textures.py` and shared by all arenas.
- **UVs + baked ambient occlusion:** `arena_builder.py` gives every face a
  world-scale planar UV0 and a unique UV1, and bakes ambient occlusion in
  Cycles to `<arena>_ao.png` (2048 px). It writes one StandardMaterial3D per
  surface to `assets/arenas/<id>/materials/`; `ArenaView` swaps them in by
  material name at load (AO on UV2). Real-time lights and shadows stay as
  they were. Godot's LightmapGI was not used because it can only be baked
  from the editor.
- **Motion (presentation only, render-frame time):** `ArenaSpin` (Origin
  heart rings), `EmissionPulse` (Origin veins, neon flicker, heart, emblems,
  crystal), a banner sway shader (Sanctuary), and a crowd shader (The Pit:
  one mesh, colour and cheering per spectator from UV data). All are in the
  `arena_fx` group where it matters, so "reduce effects" calms them.
- **Close detail** is concentrated just behind the fighters, where the
  gameplay camera actually looks.
**Accepted.**

## D-052 — 2026-11-20 — Arena pass 2: baked light, panoramas, reactions
- **Baked light:** besides AO, the builder bakes a lightmap per arena in
  Cycles: bounce light from the scene's own lights (read from the arena
  .tscn) and sky, plus the light thrown by glowing surfaces (neon, lamps,
  Origin cracks). Real-time lights stay for direct light, shadows and
  speculars; the lightmap is added as emission by
  `shaders/arena/arena_surface.gdshader` (capped near strong emitters).
- **Surface shader:** arena materials are now ShaderMaterials: tiling
  textures, world-space macro variation against visible tiling, grime that
  gathers in occluded areas (from the AO map), optional travelling glow
  (`flow`).
- **Panoramas:** the far city (Severed Line) and the cloud sea with far
  islands (Sanctuary) are rendered from the concept scenes as 4096 x 2048
  equirectangular skies (`tools/blender/arena_panorama.py`); the matching
  far geometry was removed from the game meshes.
- **Hero pieces:** conduit flanges, service pipes and exposed Origin coils;
  ring gate outer flange, carved ribs, plinth and chains; crane track
  wheels, ladder, exhaust, sheaves and hook block; heart spikes.
- **Life:** drone over the city, birds over the Sanctuary, camera flashes in
  The Pit crowd, orbiting fragments round the heart, crack glow travelling
  outward in the Origin Chamber.
- **Fight reactions (presentation only):** `ArenaView.react()` is called by
  the combat scene on hits, knockdowns and KOs: impact dust/splash/sparks,
  crowd excitement, glow flares. Off with "reduce effects".
- **Colour grading:** a per-arena 1D colour-correction curve.
**Accepted.**

## D-054 — 2026-11-20 — Owner-supplied fighter models replace the generated roster

The six playable fighters now use rigged models supplied by the owner
(Tripo exports with Mixamo-style skeletons), replacing the procedurally
generated ones: heroic warrior → Kairo, armoured warrior → Drakon, purple
hooded warrior → Nox, superhero female → Seraphina, female warrior → Vexa,
elder monk → Ryuen. Names, lore, move sets and balance are unchanged. The
bosses (Origin Sentinel, Origin Warden) keep their generated models.

`tools/blender/import_rigged.py` converts each one without changing its look:
the displayed pose is baked in as the rest shape, the display pedestal is cut
away, the mesh is scaled to the fighter's height (no decimation, 16–20k
triangles), textures are kept (re-encoded as plain JPEG/PNG so Godot can read
them) and the model is bound to the shared 18-bone fighter skeleton and given
all 17 game animations. Where the supplied rig is sound (Kairo, Drakon, Nox)
its skin weights are kept, folded onto the game bones (later only Drakon, see D-055). Three supplied rigs
were broken (Ryuen and Vexa: skeleton fitted upside down; Seraphina: spine
collapsed into the shoulders), so those are re-skinned from measured joints.
The untouched sources are kept in `assets/characters/_source/` (not imported).

Consequences: textured materials skip the toon shading and outline; a mirror
match tints P2's texture (alternate-colour costume) since these models have no
separate accent part; the Kairo skinning test allows up to 80% blended
vertices (Tripo skinning is softer than ours); `character_builder.py` skips
these six unless `--force`. **Accepted.**

## D-055 — 2026-11-20 — Fighter key/rim lights; roster re-skin fixes

Painted fighters read too dark against strong arena backlight (The Pit). Each
fighter now carries a key light (camera side) and a rim light (behind) that
light only fighters (render layer 2, light cull mask), tuned per arena in
`ArenaConfig` (warm-backlit Pit: cool key, warm rim; Severed Line: cyan rim;
Sanctuary: soft gold; Origin Chamber: crimson rim). Arena lighting is unchanged.

Pose renders from four angles showed loose parts sticking out: Kairo's sash
was skinned to his arm by the supplied rig, Nox's hood and cloak too; Ryuen's
and Vexa's measured arm joints sat inside the sleeves / short of the hands, so
hands and cuffs were left behind as long strands. Kairo and Nox are now
re-skinned (supplied joints kept), Ryuen and Vexa use arm joints read off a
measuring-grid render, and long sleeves around the middle of the arm follow
the arm. The per-fighter settings live in `tools/blender/import_roster.sh`.
**Accepted.**

## D-057 — 2026-11-20 — Motion-capture animation; mesh inspection and repair

The hand-keyed IK poses looked robotic on device. Fighter animations are now
built from real motion capture (CMU Graphics Lab Motion Capture Database,
BVH conversion; free for all uses) by `tools/blender/mocap_actions.py`:
direction-based retargeting onto the 18-bone game skeleton (torso keeps the
real hip/shoulder axes), strikes retimed so full extension lands on the
move's active frames and guided onto the hitbox centre with two-bone IK,
the boxer's guard as idle, generated footwork matched to the game's walk
speed, and reactions / knockdown / get-up / defeat / victory built from
captured poses with physical timing. Clips are fetched by
`tools/mocap/fetch_clips.sh`, not stored in the repo.

Every imported mesh is inspected and minimally repaired before skinning
(`tools/blender/mesh_check.py`): the Tripo exports were split into thousands
of pieces at texture seams (12–17k duplicate vertices), which tore the skin
weights apart when bending; exact duplicates are merged (nothing moves, UVs
kept), a few inward faces are turned outward. Triangle counts and shapes are
unchanged. The 4096 px colour maps are kept at full size; fighter colour and
normal maps use high-quality (ASTC on phones) compression. **Accepted.**

The owner regenerated all six fighters in Tripo (T-pose, no base, textured,
rigged with the Mixamo preset) and they replace the previous models and their

## D-059 — 2026-11-21 — Per-side joints, mesh-based grounding, per-fighter guards

- The converter no longer assumes a mirror-symmetric skeleton: each side's
  joints come from that side of the source rig. Averaging the two sides
  twisted Kairo's arm and hair (his shoulders differ by ~20 cm in depth);
  stretched edges in his idle went from 101 to 1.
- Every frame of every action (walks included) is grounded on the lowest
  vertex of the skinned mesh, not on the foot bone, so soles no longer sink
  into the arena floor (error ≤ 0.2 cm).
- Each fighter's guard is taken from a different captured pose and shaped
  per fighter (`STYLES` in `tools/blender/mocap_actions.py`). This is a
  visual stop-gap only: move sets are still shared (KI-049) until the
  designs in `docs/FIGHTER_COMBAT_DESIGN.md` are approved and built.
  **Accepted.**

## D-060 — 2026-11-21 — Finger bones kept; hands posed per fighter and action

The game skeleton of the six playable fighters keeps the source rig's finger
bones (three segments x five fingers x two hands = 30, 48 bones in total) with
the supplied finger weights, so fists close. The motion capture has no finger
data, so hands are posed in `tools/blender/mocap_actions.py`: a hand shape per
fighter (`HANDS`: fists for Kairo/Drakon/Vexa, lead hand open for Seraphina,
loose for Nox, open palms for Ryuen) and per-action overrides
(`HANDS_BY_ACTION`, e.g. the open-palm strike). Curl axes come from the
knuckle positions, no mesh change. Bosses keep the 18-bone skeleton.
`--no-fingers` restores the old folding. Cost on device unmeasured (KI-048).
**Accepted.**

## D-061 — 2026-11-21 — Guard height and direction + button commands

First mechanic of the per-fighter designs (`docs/FIGHTER_COMBAT_DESIGN.md`).
- **Low block:** DOWN + BLOCK (`FighterState.block_low`). MID/PROJECTILE are
  stopped by either guard, HIGH only standing, LOW only low, THROW by neither
  (`MoveData.blocked_by`). Guard height is read live during blockstun. There
  is no crouch state: hurtboxes do not change.
- **HIGH now means overhead.** Kairo's jab changed from HIGH to MID so a low
  block still stops ordinary punches; nothing else changes for existing play
  because no LOW or HIGH move exists in the data yet.
- **Commands:** `FighterInputFrame.move_y`; DOWN + LIGHT/HEAVY/KICK/SPECIAL and
  BACK + SPECIAL are separate input patterns that fall back to the plain
  button when a fighter has no such move. This gives each fighter room for
  four normals and three specials on the existing six touch buttons.
- **AI:** `AIProfile.low_block_chance` (beginner 0.15, standard 0.5, expert
  0.9) decides whether it guards a LOW/HIGH attack at the right height.
- **Animation:** `<FIGHTER>_BLOCK_LOW` for the six playable fighters
  (`anim_block_low`; bosses fall back to the standing block); the block
  shield drops with the guard.
**Accepted.**

## D-062 — 2026-11-21 — Kairo's own move set; counter stances

First fighter built from `docs/FIGHTER_COMBAT_DESIGN.md`.
- **Moves (data/moves/):** `kairo_low_kick` (KICK, LOW, replaces the shared
  front kick for Kairo only), `kairo_body_hook` (DOWN + HEAVY),
  `kairo_slip_counter` (BACK + SPECIAL) and its follow-up
  `kairo_counter_hook` (no input of its own). Jab now also cancels into the
  body hook; low kick cancels into jab. The other five fighters and the bosses
  keep the shared `kairo_*` set (incl. `kairo_kick`) until their own sets.
- **Counter stance (engine):** `MoveData.counter_start_frame/_end_frame/
  _levels/_followup/_stun_frames`. A counter move has no hitbox; an attack of
  a listed hit level that connects during the window does no damage, its user
  is frozen (`counter_stun_frames`) and the follow-up starts at once
  (`CombatEvent.Type.COUNTER`). Slip Counter catches HIGH and MID, so lows
  (and later throws) beat it.
- **Animation:** body hook and counter hook are captured hooks from the boxer
  clip (frames 2214 and 3342, found by elbow angle and lateral hand speed);
  the slip is keyed from his guard; the low kick is the captured front kick
  guided to shin height — a low push kick, not the roundhouse low kick of the
  design (no capture of one).
- **Pipeline:** `export_move_timing.gd <out> <fighter>`; each fighter is
  animated from its own move data (`/tmp/moves_<id>.json`).
- **AI:** uses DOWN + button moves it has; `AIProfile.counter_chance`
  (standard 0.12, expert 0.3).
- **Not built from the design:** the low kick's brief walk-speed slow.
**Accepted.**
